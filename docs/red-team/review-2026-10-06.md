# Initial adversarial review — local router core

Date: 2026-10-06
Scope: `tbaf.review-input/v1` parser, local CLI, deterministic router.
Method: source review plus the contract checks under `tests/`. This is not an audit of a GitLab integration; none exists yet.

## Findings

### High — check provenance is caller-asserted

The input can label a check `PASS` and provide a source name, version, revision, scope, and artifact reference. The CLI validates shape and revision equality but does not authenticate the CI producer, establish that the artifact exists, or bind it cryptographically to the stated commit and scope. A caller can therefore produce a `COVERED_BY_EVIDENCE` receipt from fabricated input.

**Disposition:** limitation documented. Before integrating a live provider, add an authenticated evidence-ingestion boundary that verifies the CI identity, immutable run/artifact, exact commit, and check scope. Until then, treat receipts as deterministic evaluations of supplied records, not attestations about a real MR.

### High — policy storage and scope completeness need a trusted integration boundary

MR data and policy are separate inputs, so an MR record cannot override claims, required checks, or capacity. The CLI does not enforce where the policy file comes from, however. The router also cannot detect a missing or overly narrow glob in policy. A file that should affect a protected claim but falls outside the configured patterns can be omitted from that claim's evaluation.

**Disposition:** load policy from a protected, versioned source; review its path coverage with a representative corpus; preserve its commit/hash provenance. The local CLI remains a prototype and cannot enforce repository protection on its own.

### Medium — estimates use best-fit whole tasks

The scheduler only schedules a task if its entire declared estimate fits the remaining budget. Its current single-MR ordering is consequence-first and deterministic; it does not model reviewer expertise, partial work, or team-level fairness.

**Disposition:** acceptable for the single-MR Level 1 core. The Level 2 scheduler must define assignment and cutoff semantics before it is treated as a team planner.

## What the current checks establish

The local checks cover exact-revision matching, missing/failed checks, unmapped paths, candidate non-authority, stale observations, bounded parsing, reproducible serialization, and visible unknown effort. They do not measure detection rates, benign escalation, reviewer time, provenance authenticity, or real GitLab behavior.
