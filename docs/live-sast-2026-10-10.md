## Candidate finding

Both observed reports contain one finding: `bandit.B101`, “Improper check for
unusual or exceptional conditions,” severity `Info`, at
`src/tbaf/auth_invariants.py:126` (`assert statement.value is not None`). In
MR !12, that path is not changed. Therefore this repository-wide scan result
is not attributed to !12's changes and must not be linked as a candidate
observation in !12's Review Package.

This is an informational static-analysis observation, not an established
security vulnerability. `_validate_statements` checks return statements before
`_execute_statements` is called and rejects a return with no value as
`_UnsupportedSyntax`. The outer check converts unsupported syntax to `NOT_RUN`,
which keeps the authorization claim unresolved. Removing Python assertions
under optimization therefore does not appear to create a fail-open path in this
code. Replacing the assertion with an explicit guard remains a possible cleanup;
the finding is not suppressed here.
